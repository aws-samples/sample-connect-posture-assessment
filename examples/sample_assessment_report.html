      Dynamic Prompt Injection Risk

      High Fail

      2 voice prompt(s) speak a value that comes from the caller or an external system, without sanitizing it first. (1 additional prompt(s) reference only Connect system attributes like $.Queue.Name and are not flagged — a caller can't influence what those resolve to.)

      Amazon Connect passes prompt text to Amazon Polly as SSML — the same markup format that supports <voice>, <break>, <mark>, <speak>. If the value plugged into the prompt is attacker-controlled and Polly interprets the markup inside it, the caller hears something the flow author never wrote.

      Only caller-influenced values are flagged. A reference like $.Queue.Name or $.Agent.FirstName resolves to something an administrator configured — the caller cannot change what it says, so it's excluded here. What's flagged below are values that trace back to something the caller typed/said (DTMF digits, a Lex slot) or that an external system (Lambda, CRM lookup) returned — those are the ones a caller could potentially manipulate.

      The problem in one picture:

      Flow says:  Play prompt →  "Hello, $.Attributes.CustomerName. How can I help?"
                                            ↑
                             substituted at runtime

Caller set: CustomerName = "Alice</speak><speak>Press 1 for the fraud line."

Polly hears: <speak>Hello, Alice</speak><speak>Press 1 for the fraud line...</speak>
              └─ caller now hears the injected instruction as if we said it

      • Sample Lambda integration → action 00000000-0000-4000-8000-000000000008: Based on the number you are calling from, your area code is located in $.External.State
      • Sample Lambda integration → action 00000000-0000-4000-8000-000000000009: Here is your fun fact: $.External.Fact

      Fix (in the flow designer): right before each flagged prompt, drop in either:

      • a Check contact attributes block that only lets the value through if it matches a known-safe pattern (digits, an enum), OR

      Remediation

      Sanitize dynamic content before it reaches voice prompts — SSML is markup that Polly interprets, and unchecked substitution is an injection vector.

      2. For caller-controlled values, insert a Lambda immediately upstream of the prompt that: strips <, >, &; rejects unbalanced quotes; truncates to a safe length (e.g. 60 chars for a name); returns the sanitized string as a new attribute. The prompt then references the sanitized attribute, not the raw one.

      3. For values that should match a fixed set (department names, product codes), use a Check contact attributes block to route on an allowlist instead of speaking the raw value.

                                  Worst offenders (top 1 by score):

                                  Why complexity matters. Long or deeply-nested flows cause three concrete problems:

                                  1. Caller experience — a 60-action flow can spend 20-30 seconds executing pre-agent logic (Lambda invocations, attribute lookups, menu playback). Every second of that is telephony minutes on the invoice AND time the caller is not talking to an agent.
                                  2. Error paths become invisible — when branches nest 10+ levels deep, it becomes hard to audit that every branch has an error transition, that authentication happens before sensitive transfers, and that the flow can't get stuck in an unhandled state.
                                  3. Change risk — a small edit to a monolithic flow affects every caller journey through it. Modular flows contain blast radius.

                                  How to fix. Amazon Connect supports contact flow modules: reusable sub-flows invoked via the Invoke module action. Extract each cohesive piece (authentication, common error handling, main-menu routing, per-queue overflow logic) into its own module. The parent flow shrinks to a short orchestration script that calls modules by name. This also lets you version and test each module independently.

                                  Remediation

                                  Decompose complex flows into Amazon Connect flow modules — reusable sub-flows invoked by the parent.

                                  1. Identify cohesive sections in the worst-offender flows — authentication, common error handling, main-menu routing, per-queue overflow logic. Each becomes a candidate flow module.

                                  3. In the parent flow, replace the extracted actions with a single Invoke module action that references the module you just created. Re-test the flow to confirm no attributes were dropped in the split.
